# Codebase Audit — 2026-07-02

Full static audit of vfx-explorer: performance, edge cases, logic errors, security, reliability.
Five subsystem passes (block sync/Celery, models/CLI client, vBTC API/BTC clients, general API, shop/payment/misc),
with the highest-impact findings independently re-verified against source. No code was changed.

Severity: **C** critical (money/data loss or trivially exploitable), **H** high, **M** medium, **L** low.

---

## 1. Block sync & Celery (rbx/tasks.py, sync_blocks, celery.py)

### C1. `sync_block` is non-atomic and non-idempotent → permanent partial blocks
`rbx/tasks.py:146-264`. No `atomic()` wrapper (the `atomic_transaction` import at line 13 is never used).
`Transaction.objects.create(hash=...)` on a PK means any re-execution of a synced block raises `IntegrityError`
on the first tx. Any exception mid-loop leaves a partial block: block row exists, some balances applied, rest missing.
The sync cursor is `max(height)+1` and `backfill_missing_blocks` only finds missing *heights*, never partial blocks —
so the corruption is permanent and silent. Retries also re-increment `master_node.block_count` (incremented *before*
`get_or_create`, full-object `save()`).
**Fix:** wrap per-block body in `atomic()`; `get_or_create` transactions and skip balance/process steps for existing
ones; move `block_count` increment behind `if block_created:` using `F("block_count") + 1`.

### C2. Re-syncing block 0 wipes the Address table; genesis-only DB loops the wipe
`rbx/tasks.py:154-155` — `sync_block(0)` runs `Address.objects.all().delete()` unconditionally.
`sync_blocks.py:32` — `start_height = 0 if sync_all or not local_max_height else ...` treats height 0 as "no blocks",
so a DB containing only genesis restarts at 0 every 10-second beat tick, wiping addresses each time (then crashing on
duplicate tx create per C1). Also fires on `backfill_missing_blocks --heights 0`.
**Fix:** `local_max_height is None` for the emptiness check; move the wipe out of `sync_block` into the `--wipe`
command path (or gate on `block_created`).

### H1. ADNR fee guard compares a model instance to a string — always True
`rbx/tasks.py:224` — `to_address != "Adnr_Base"` where `to_address` is an `Address` instance; Django model `__eq__`
vs `str` is always False, so the `!=` guard always passes and the 5 (or 1) VFX ADNR fee is deducted from **every**
ADNR recipient including `Adnr_Base` itself. Balance drift on the pseudo-address.
**Fix:** compare `tx.to_address != "Adnr_Base"`.

### H2. No timeouts + no task time limits can stall the concurrency=1 blocks-worker forever
Only `health_check` has time limits (`project/celery.py:56`). In the sync hot path: `get_nft`
(`rbx/client.py:477`, no timeout, retries 5×5s synchronously), `notify_socket_service` (`rbx/tasks.py:1536`, no
timeout **and** no try/except — a down socket service aborts the catch-up round), and `process_shop` calls
`import_shop` synchronously (shop-crawler dance with multi-attempt sleeps). One hung CLI response stalls all block
sync with no exception for Sentry.
**Fix:** `timeout=` on every request; try/except around `notify_socket_service`; `time_limit` on `sync_the_blocks`;
dispatch `import_shop.apply_async()` to the default queue.

### M1. Blocks silently skipped when node returns bad data; backfill is manual-only
`rbx/tasks.py:150-152` — `if not data: return` while the cursor advances. `backfill_missing_blocks` is not in the
beat schedule. **Fix:** raise `RBXException` on empty payload (autoretry handles it) and/or schedule the backfill.

### M2. Lost-update races on `MasterNode` between blocks-worker and default-worker
`rbx/tasks.py:158-161` vs `113-132` — both do read-modify-write full saves; last writer clobbers `block_count` or
`is_active`. **Fix:** `F()` update for block_count; `update_fields` in `sync_master_nodes`.

### M3. `Recover()` handler crashes on existing recovery address
`rbx/tasks.py:623` — `Address.objects.create(address=new_address)` on a PK → `IntegrityError` if the address exists
(it usually does), aborting the block mid-loop (see C1). **Fix:** `get_or_create`.

### M4. `Decimal(float)` on monetary amounts throughout ingestion
`rbx/tasks.py:208-209, 817, 901, 939, 982-983` — CLI JSON parses amounts as float; `Decimal(float)` preserves binary
error inside the 16 stored decimal places; accumulated balances drift.
**Fix:** `response.json(parse_float=Decimal)` in `client.py` (at least `get_block`), or `Decimal(str(x))`.

### M5. `sync_block_count` / `resync_balances` materialize entire tables
`rbx/tasks.py:1304-1320, 267-290` — amplified by the `BlockManager` default prefetch (see §2 H3): loads every block
*plus every transaction on the chain* into memory, then per-row UPDATEs. `resync_balances` deletes all addresses
first, so live reads see empty balances for the duration.
**Fix:** replace with grouped aggregate SQL; add a plain manager for sync-path lookups.

### M6. Beat enqueues `sync_the_blocks` every 10s with no `expires` — backlog during catch-up
`project/celery.py:22, 49-53`. **Fix:** `expires=10` on the periodic task.

### M7. `WwwRedirectMiddleware` executes the view before redirecting
`project/middleware.py:10-17` — a POST to a `www.` host runs its side effects, then 302s and the client replays them
against the apex host (duplicate side effects). `host.replace("www.", "")` also replaces anywhere, not just prefix.
**Fix:** check host and redirect *before* `self.get_response(request)`; use `removeprefix`.

### Low
- `rbx/utils.py:31-32`, `rbx/tasks.py:1325` — `get_info()`/`get_topics()` can return `None`; callers TypeError.
- Swallowed exceptions: bare `except:` at `rbx/tasks.py:64-67`; `network_metrics` returns None on any exception
  (`rbx/utils.py:52-54`, plus stray `print(data)`); `TransferCoinMulti` errors go to `print("ERROR")`
  (`rbx/tasks.py:922-924`) — invisible to Sentry.
- `rbx/tasks.py:196-199` — `timezone.make_aware(datetime.fromtimestamp(ts))` interprets epoch in OS-local tz;
  correct only while everything is UTC. Use `datetime.fromtimestamp(ts, pytz.UTC)` (as line 183 does).
- `rbx/tasks.py:1460, 1490, 1519` — `NamedTemporaryFile(delete=False)` never unlinked; worker disk fills.
- No reorg detection: `get_or_create(height=...)` never compares stored hash to node's response.
- `rbx/utils.py:72` — `data.replace("\x00", ...)` result discarded (no-op).

## 2. Models & CLI client (rbx/models.py, rbx/client.py, admin, views)

### H1. Nearly every HTTP call to the CLI has no timeout
`rbx/client.py` — get_status, get_master_nodes, tx_get_fee/tx_get_hash/tx_verify/tx_send, get_nft,
verify_nft_ownership, get_topics, get_active_connections, get_vbtc_compile_data, send_testnet_funds, withdraw_btc,
all shop/bid functions. Only get_info, get_block, and the vBTC-V2 helpers set timeouts. Given the CLI's known
cold-start hang, one stalled response pins a gunicorn worker or wedges a concurrency=1 Celery queue. `withdraw_btc`
is a money path with no timeout, no status check, unguarded `.json()`.
**Fix:** shared default `timeout=(5, 30)` on every call (route through a helper like `_vbtc_v2_request`).

### H2. `get_active_connections` returns `False` where callers iterate a list
`rbx/client.py:591-618` — returns `False` on non-200 / `Success != True`; `is_already_connected_to_shop` does
`for shop in active_shops:` → `TypeError`, crashing `connect_to_shop` / `send_raw_bid` / `get_shop_data`.
Unguarded `response.json()` too. **Fix:** return `[]`; guard the parse.

### H3. `BlockManager` globally prefetches all transactions for every Block queryset
`rbx/models.py:85-92` — default manager bakes in `prefetch_related("transactions")`; every admin page, API list, and
sync-path `Block.objects.get(...)` pays for transactions it never uses; whole-table querysets OOM (see §1 M5).
**Fix:** drop prefetch from the default manager; add it at call sites that need it.

### H4. `VbtcToken.addresses` N+1 per transfer row, serialized in list endpoints
`rbx/models.py:1095-1114` — reads `t.transaction.to_address/from_address` per transfer with no
`select_related("transaction")`; `VbtcTokenSerializer` exposes it `many=True` → tokens × transfers queries.
**Fix:** `select_related("transaction")`, or denormalize to/from onto the transfer row as V2 already does.

### M1. `stats_view` crashes with `Decimal(None)` on empty aggregates
`rbx/views.py:33, 53, 78` — `Sum()` returns `None` on empty sets. **Fix:** `Decimal(q["..."] or 0)`.

### M2. `callback_details` / `recovery_details`: unguarded JSON parse + per-row queries in list serializers
`rbx/models.py:221-244` — `json.loads(self.data)` then `parsed["Function"]` with `data` nullable; one bad RESERVE
row 500s every list page containing it; also 2 extra queries per RESERVE row. **Fix:** guard None, `.get()`,
try/except; drop from list serializers.

### M3. Duplicate `validate_signature` definitions — the live one can raise KeyError
`rbx/client.py:431-444` vs `538-551` — second shadows first; catches `IndexError` but does `data["Result"]`
(KeyError uncaught); the two hit different URLs. **Fix:** delete one; catch KeyError / use `.get()`.

### M4. `get_address_nonce` logs `response.json()` before error handling
`rbx/client.py:391` — debug log parses the body before the guarded parse; cold-start plaintext body →
`JSONDecodeError` the handler never sees. **Fix:** log `response.text`.

### M5. Admin pages that will crawl or time out at scale
- `NftAdmin` (`rbx/admin.py:236-244`): `transaction_count` (3 counts) + `is_listed` (exists) per row ≈ 400
  queries/page. **Fix:** annotate in `get_queryset`.
- `TransactionAdmin` (`rbx/admin.py:183-191`): `unlock_time` EmptyFieldListFilter (unindexed) and `icontains`
  search on the biggest table — also the autocomplete target for vBTC admin FKs, so each keystroke scans.
  **Fix:** index `unlock_time` (partial), prefix/exact search fields.

### M6. `Address.get_balance` parses every NFT_SALE tx in Python with float→Decimal
`rbx/models.py:562-586` — unbounded per-row `json.loads` in an API hot path (address detail, faucet), same
null-`data` crash surface as M2, and `Decimal(sub["Amount"])` from float. **Fix:** guard + `Decimal(str(...))`;
consider materializing sale sub-transactions.

### M7. `send_testnet_funds` returns arbitrary error text as a tx hash
`rbx/client.py:1029-1038` — only two exact failure strings checked; any other failure text is stored as a
"transaction hash" and the faucet send is treated as successful. **Fix:** only accept responses starting with
`"Success! TxId: "`.

### M8. `get_nft` ignores HTTP status and blocks the sync worker while retrying
`rbx/client.py:466-482` — returns error JSON bodies as contract data; non-JSON bodies retry 5× with `sleep(5)`
inside the concurrency=1 worker. **Fix:** status check, validate shape, timeout.

### M9. Bid pipeline: uncaught KeyErrors; `send_raw_bid -> bool` never returns True; double-encoded JSON body
`rbx/client.py:901-957`. **Fix:** catch KeyError/use `.get()`, return real booleans, pass dict to `json=`.

### Low
- `Nft.readable_code` no-op replace + crashes on empty data (`rbx/models.py:407`) — currently unused.
- `Price.created_at`/`NetworkMetrics.created_at` use `auto_created=True` (internal flag, does nothing) instead of
  `auto_now_add` (`rbx/models.py:806, 826`). NetworkMetrics nullable `created_at` also crashes
  `api/views.py:network_metrics` on fresh DBs (`None < datetime`).
- Dead client functions with latent form-encoding bug (`rbx/client.py:403-459`) — delete.

**Verified sound:** V2 ledger math (`ledger_entries` / `settlement_amount_for` / owner anchor) reconciles in all
traced scenarios; withdrawal cancel-vs-complete ordering handles cross states; `(token, transaction)` unique
constraint guards ledger double-count.

## 3. vBTC API & BTC clients (api/btc/, btc/)

### C1. FROST withdrawal signing runs in an unmanaged daemon thread with no idempotency guard
`api/btc/views.py:516-573` — `threading.Thread(target=_run_frost, daemon=True).start()` inside gunicorn.
(1) Worker recycle/deploy kills the thread mid-ceremony; a completed CLI-side ceremony's signed BTC tx can be lost.
(2) No lock on `withdrawal_request_hash`: a double-click launches two concurrent FROST ceremonies; if the CLI
coin-selects different UTXOs, both signed txs are broadcastable — **double payout**.
**Fix:** move to a Celery task on the vbtc-worker queue (already concurrency=1); gate with
`cache.add(f"frost_lock:{hash}", job_id, TTL)` returning the existing job on duplicates.

### C2. `BtcExplorerClient` hardcoded to testnet — mainnet `/api/btc/address/` serves testnet data
`btc/client.py:13` — `network = "testnet"` class attr, never overridden (unlike `BtcClient` which switches on
`settings.ENVIRONMENT`). Balances/transactions/UTXOs for any address are wrong-network on prod, and cached.
**Fix:** derive from `settings.ENVIRONMENT`, or retire the endpoint in favor of `BtcClient`.

### H1. No ownership/authorization checks on any vBTC money-moving endpoint
`api/btc/views.py` — no view sets `permission_classes` or binds the caller's AuthToken to the address being operated
on (shop endpoints do, via `address_permission`). Anyone can invoke withdraw-complete prepare/execute with someone
else's `sc_identifier`, or `VbtcV2CeremonyPrepareView` with arbitrary `owner_address` (each call triggers MPC
ceremony prep across validators) at the default 300/min throttle. CLI signature validation is the only gate and the
expensive *prepare* endpoints don't require one.
**Fix:** `address_permission`-style checks on prepare/execute; tight `ScopedRateThrottle` (e.g. 5/min) on
ceremony-prepare, FROST-execute, compile-data.

### H2. `VbtcListAllView`: blacklist bypass + full-table N+1 + dead code
`api/btc/views.py:148-173` — final query has no `.exclude()`, so blacklisted tokens reappear once they have any
transfer row; iterates every `VbtcTokenAmountTransfer` touching `transfer.token` (query per row); first queryset is
dead. **Fix:** `VbtcToken.objects.exclude(sc_identifier__in=BLACKLIST)` — the transfer scan adds nothing. Paginate.

### M1. `VbtcCompileDataView`: up to 5 no-timeout upstream calls + 15s of sleep per request
`api/btc/views.py:86-104`, `rbx/client.py:988-1010`. **Fix:** timeouts; single attempt or client-side polling.

### M2. FROST job status deleted on first read — dropped response loses the signed tx
`api/btc/views.py:592-601` — delete-on-read; a network blip means 404 forever and a re-run of the whole ceremony
(re-raising C1). **Fix:** let the TTL expire; reads are idempotent.

### M3. `VbtcV2DetailView` GET walks the provider chain inline (worst case ~60s per worker)
`api/btc/views.py:227-254`, `btc/btc_client.py:62-80` — 4 providers × (5,10)s timeouts in the request thread during
provider outages; per-token throttle key means N tokens pin N workers. **Fix:** dispatch refresh to Celery and serve
the stored row, or cap the chain walk with an overall deadline.

### M4. `sc_identifier` not unique on `VbtcToken`/`VbtcV2Token`
`rbx/models.py:1064, 1131` — creation is get/except-then-save; safe only single-writer, but `backfill_missing_blocks`
can run concurrently with the blocks-worker and insert duplicates → `MultipleObjectsReturned` → permanent 500 on the
detail endpoints. **Fix:** UniqueConstraint (dedupe first); `update_or_create` in the Mint handler.

### M5. `BtcTx.timestamp` is assigned the transaction hash
`btc/models.py:45` — `self.timestamp = data["transactionHash"]` (copy/paste). **Fix:** use the timestamp field.

### M6. `BtcExplorerClient`: no timeouts, no status checks, unguarded deep indexing
`btc/client.py:24, 43-47, 62-66` — hangs or KeyError-500s on provider errors (contrast `btc_client.py:86-89` which
does it right). **Fix:** `timeout=(5,10)`, `raise_for_status()`, map to 502/503.

### M7. Serializer N+1s and unpaginated vBTC list endpoints
`api/btc/serializers.py:71-97`, `views.py:190-276` — per token: `addresses` property queries + per-withdrawal FK
fetches (`request_transaction`/`completion_transaction`) + `nft` fetch; `VbtcV2ListAllView` serializes every token
unpaginated; `VbtcV2ListView` loops transfers without `select_related("token")`.
**Fix:** select/prefetch related, `values_list("token__sc_identifier")`, paginate, keep `addresses` detail-only.

### M8. Ownership-transfer signature travels in the URL path of a side-effecting GET
`api/btc/urls.py:68`, `views.py:686-701` — signatures land in gunicorn/Porter/proxy logs; GETs are replayable by
prefetchers. **Fix:** POST with the signature in the body.

### Low
- `btc_client.py:169-210` — provider chain covers only `get_balance`; `get_transactions` still solely
  blockchain.info (the endpoint whose 429s caused the incident); `broadcast_transaction` solely blockstream.
  Extend chain; add mempool.space broadcast fallback.
- Blockdaemon rung returns `None` for unknown addresses instead of zero-balance partial (`btc_client.py:114-125`).
- `_vbtc_v2_proxy` / ceremony status leak raw CLI payloads in error bodies (`views.py:285-288, 369, 373`).
- `BtcBroadcastView` is an open BTC relay (`views.py:729-750`) — scoped throttle; optionally require a matching
  in-flight withdrawal.
- `update_vbtc_balances` sweep grows linearly; will overlap its window (`btc/management/commands/...:20-40`).

**Verified sound:** provider-chain money math is all-Decimal; `partial` flag honored by both callers; targeted
`update()` not racy `save()`; withdrawal cancel/complete cross-state handling.

## 4. General API layer (api/*, excluding btc/shop)

Context: with `API_AUTH_REQUIRED` false (public explorer), every view without an explicit permission class is
anonymous; global throttle 300/min/IP.

### Broken endpoints (every request 500s)
- **`RetrieveSmartContractView`** — route `retrieve-smart-contract/` has no `<id>` param but the view reads
  `kwargs["id"]` → KeyError (`api/raw/views.py:85-90`, `urls.py:33`).
- **Chat message list** — `filter(thread_uuid=...)` but the field is `thread` FK → `FieldError`
  (`api/chat/views.py:104`). Fix: `thread__uuid`.

### H1. Chat is completely unauthenticated (read, write, delete)
`api/chat/views.py:29-134` — anyone can list a buyer's threads by address, read full history, post as either party
(`is_from_buyer` is client-supplied), and `delete()` destroys any thread by uuid (plus 500 on missing uuid).
**Fix:** `address_permission` on all chat endpoints; derive `is_from_buyer` from the authenticated address; 404 on
missing.

### H2. Unauthenticated writes: master node registry poisoning
`api/master_node/views.py:99-154` — no auth on `SendMasterNodesView.post`; also echoes exception internals and
forwards upstream with no timeout. **Fix:** shared secret, payload validation, timeout, Celery for the forward.

### H3. Unauthenticated S3 upload + arbitrary NFT media overwrite
`api/media/views.py:24-90` — 150MB public-read uploads with client-controlled filenames at 300/min (free
malware/phishing hosting + S3 cost); `AssociateMediaView` sets `nft.asset_urls` for **any** NFT to an arbitrary dict.
**Fix:** ownership auth on both, content-type allowlist, filename sanitization, tight throttle.

### H4. Faucet: withdrawal-limit bypass + double-send race + SMS pumping
`api/faucet/views.py:76-161` — the per-phone limit only counts completed rows and is never re-checked at verify:
create N pending requests, verify all, drain N× the limit. Two concurrent verifies of the same uuid both pass the
`transaction_hash` check → double `send_testnet_funds`. Every request POST fires a Twilio Verify SMS to an arbitrary
number (SMS-pumping fraud) with only the global throttle.
**Fix:** re-check cumulative limit inside verify under `select_for_update`; "sending" marker before the CLI call;
scoped throttle (e.g. 3/hour/IP) + per-phone cooldown on request.

### H5. Path injection / SSRF into the CLI via unencoded URL interpolation
`rbx/client.py:538-541, 431-434, 1023-1026` — client-supplied `message/address/signature` interpolated raw into CLI
URLs (`.../{message}/{address}/{signature}`); via `<path:>` or JSON body they can contain `/`, `../`, `?` and
redirect the server-side request to arbitrary CLI endpoints. **Fix:** `urllib.parse.quote(v, safe="")` every
segment; reject `/` in inputs.

### H6. Auth-token minting: signature replay + weak randomness + unthrottled login
`api/auth/serializers.py:48-64` — no server-issued nonce/timestamp/domain binding: any signature the address ever
produced over any public message can mint a 1-hour AuthToken — and every tx's `signature` is publicly exposed by the
transaction API. Tokens generated with `random.choice` (`project/utils/string.py:7`, not CSPRNG). DRF's
`ObtainAuthToken` sets `throttle_classes = ()` so `/api/auth/token/` has **no** throttle (brute force).
**Fix:** server-side nonce challenge; `secrets.token_urlsafe`; subclass ObtainAuthToken with throttles. Also index
`AuthToken.token` (unindexed TextField scanned on every permission check, `access/models.py:107`).

### H7. Full-table scans in request paths
- `AddressTopHoldersListView` (`api/address/views.py:36-83`): groups all transactions with a correlated subquery per
  request, uncached — DoS vector. Precompute in Celery.
- `circulation`/`circulation_balance`/`lifetime_balance` (`api/views.py:13-76`): call `sync_circulation()`
  **synchronously** (~6 full-table aggregates) when stale, no cache/lock → request stampede; response built from the
  pre-sync stale row anyway. Use `.delay()` + serve stale.
- `network_metrics` also makes a synchronous CLI HTTP call in-request.

### H8. `TransactionSerializer` N+1 explosion
`api/transaction/serializers.py:31-54` — per row: `nft` FK (no select_related on the base queryset),
`callback_details`/`recovery_details` (JSON parse + up to 2 queries per RESERVE row, nested SubTransaction with
another `nft`). `limit=500` pages → 1,000+ queries. `AdnrSerializer` nests the full TransactionSerializer, so
`AddressListView` (uncached) inherits all of it.
**Fix:** `select_related("nft")`; drop callback/recovery from list serializers; slim AdnrSerializer for lists.

### H9. Fungible-token endpoints: per-row property queries and per-holder aggregation
`api/fungible_token/serializers.py:5-30`, `views.py:38-63` — `description` (Nft.get per row), `created_at` (FK load
per row), `circulating_supply` (2 aggregates per row); detail view loops every historic address ×
`get_address_balance` (4 aggregates each) — ~4,000 queries per uncached GET for a 1,000-address token.
**Fix:** one grouped query for holders; select_related; cache.

### Medium
- `/api/transaction/block/0/` 500s: `if not height: return []` treats genesis as missing, then the ordering filter
  calls `.order_by` on a list (`api/transaction/views.py:34-39`). Use `Transaction.objects.none()`.
- Unguarded `json.loads(tx.data)` / `data["Function"]` in `api/address/views.py:128-134` (+ models sites) — one
  malformed on-chain payload poisons address detail, balances, list pages.
- `?search=` is `icontains` over hash/to/from on the transactions table — full scan; `StandardPagination` also runs
  a full `COUNT(*)` per page (`api/pagination.py:15-17`). Exact/prefix match or trigram; cursor/estimated counts.
- Non-unique `.get()` 500s: MasterNode by non-unique `name` (`api/master_node/views.py:79-85`); Adnr domain
  non-unique + case-sensitive (`api/address/views.py:187`); faucet uuid as CharField → ValidationError not
  DoesNotExist (`api/faucet/views.py:120`).
- `NftHistoryView` crashes when `mint_transaction` is NULL (`api/nft/views.py:82-95`).
- `NftSerializer.is_listed` is a per-row exists query (`api/nft/serializers.py:24`) — annotate instead.
- Faucet amount formatting: `str(Decimal("100").normalize())` → `"1E+2"` into the CLI URL (`rbx/client.py:1023`) —
  verified users requesting round amounts burn their verification. Use `format(d, "f")`.

### Low
- `api/raw/views.py:198` — `{result: None}` uses the *variable* as dict key (JSON key `"null"`); line 15
  `raise NotImplemented()` should be `NotImplementedError`.
- `ValidateSignatureView` returns 500 for an invalid signature (indistinguishable from failure).
- Beacon upload/assets are side-effecting GETs (`api/raw/views.py:146-182`).
- `AddressView`: `order_fields` is not a DRF attribute (silent no-op); Search/Filter backends inert.
- `api/permissions.py:20-34` — case-sensitive `replace("basic ", "")` anywhere-in-string; `print()` for auth
  failures.
- `api/filters.py:1` — `distutils.util.strtobool` removed in Python 3.12 (latent upgrade break).
- `LatestChatMessagesView` unconditionally returns `[]`; dead code below contains a Q-precedence bug.
- 204 response with a JSON body (`api/chat/views.py:97`).
- `api/cmc_price` returns success on empty table; `api/views.py:84-117` `applications` serves hardcoded stale data.

**URL ordering (project convention):** no catch-all shadowing violations found in scope.

## 5. Shop, payment, access, connect, price

### H1. `handle_auction_sale_complete_tx` NameError on missing transaction
`shop/tasks.py:498-504` — `except Transaction.DoesNotExist: print(...); pass` then falls through to
`json.loads(tx.data)` with `tx` unbound. Any sale-complete tx not yet indexed crashes the task.
**Fix:** `return` in the except block.

### H2. MoonPay signature endpoint is an unauthenticated signing oracle
`payment/views.py:24-60` — `@csrf_exempt`, no auth/throttle, HMAC-signs **any** caller-supplied query string with
the merchant secret; attacker gets validly-signed MoonPay widget URLs with arbitrary wallet/amount/redirect params.
**Fix:** auth + reconstruct the query server-side from a whitelist of expected params before signing; throttle.

### M1. Shop list endpoints N+1 (no eager loading with deeply nested serializers)
